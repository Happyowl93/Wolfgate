# Xenoarch

Wolfgate runs wizden's xenoarchaeology rework (artifacts as a graph of nodes, each with its own triggers and an
effect, unlocked from the analysis console) instead of the old node-tree artifacts. It is ported from Frontier,
which keeps its sector tweaks: no artifact activations or portal pulls on protected grids, single-use nodes
(`nf14.xenoarch.single_use_nodes`), a trimmed effect pool and slower unlocking. On top of that come later wizden
fixes, the artifact lamp effects, the microwave, interact-with, shock, stamina, particle and laser triggers, the
trigger continuation popup, artifact glue, the predicted-random effect cleanup, the reworked guidebook pages, and
wizden's trigger rewrite: triggers are entity prototypes rolled from an entity table, with balanced generation.
That rewrite brought wizden's upgraded `Content.Shared/EntityTable` (conditions, context, `IRobustRandom`); the old
`GetSpawns(table, System.Random)` overload is kept for existing callers. The game-rule conditions (budget, player
count, round duration, rule occurrence) were left out, since nothing here uses them.

Wolfgate's own changes: the old Mono artifact gases (BZ, healium, nitrium, pluoxium) are effects in
`Resources/Prototypes/_WF/Xenoarch`, the gun effect uses Mono's .357 ammo, a fully unlocked artifact sells for
about 0.6 × its research value (around 47k spesos on average), the ASF artifact bounties match the new
`XenoArtifact` component, and hitscans raise `HitscanRaycastStrikeEvent` on what they hit (after ship shields), so
any hitscan beam counts for the laser trigger.

Players scan artifacts with an analyzer linked to an analysis console, perform the listed triggers, and extract
research points from the console. Admins use the `xenoartifact` toolshed commands (`spawnartwithnode`,
`createnode`, `unlocknode`, `removenode`, ...).

Not ported: wizden's predicted crusher and its sound fix; our crusher runs server-side, so the repeating-sound bug
doesn't occur.
